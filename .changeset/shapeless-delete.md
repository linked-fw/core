Shapeless delete: `Shape.delete(ids)` on the base class deletes nodes whose types the caller does not know. Every triple whose subject is one of the ids, and every triple that links to one, is deleted in every graph of the dataset: each named graph and the default graph (never by way of `graphs.union`), with or without graph routing. `_keepingIncoming()` keeps the links. IR kind `delete_shapeless`; DSL-JSON 1.3 `{op: 'delete', mode: 'shapeless', ids}` (no shape); SPARQL one update (`VALUES ?x`, the default graph's own pattern, and `GRAPH ?g { {?x ?p ?o} UNION {?s ?p2 ?x} }` over every named graph; `deleteShapelessToSparql`). A dataset is sent one only when it lists the new query feature `'shapelessDelete'` in `supports` (`SparqlDataset` does). `LinkedStorage` sends one without a target to every dataset, after checking all support it, with the fan-out notice. It reaches every graph, so a receiver that runs it for a client decides who may send it. `DeleteQuery.shape` (and `DeleteBuilder.shape`) is now `NodeShapeData | undefined`; `DeleteBuilder.isShapeless` and `requiredFeatures()` are new.
