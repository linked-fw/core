Shapeless delete: `Shape.delete(ids)` on the base class deletes nodes whose types the caller does not know. Every triple whose subject is one of the ids, and every triple that links to one, is deleted in every data graph of the dataset: the default graph and each named graph, with or without graph routing (never by way of `graphs.union`, and never the graph registry or a graph it records as a `core:ShapesGraph` or `core:OntologyGraph`). `_keepingIncoming()` keeps the links. IR kind `delete_shapeless`; DSL-JSON 1.3 `{op: 'delete', mode: 'shapeless', ids}` (no shape); SPARQL one update (`VALUES ?x`, the default graph's own pattern, and `GRAPH ?g { {?x ?p ?o} UNION {?s ?p2 ?x} }` over every named graph but the structure graphs; `deleteShapelessToSparql`). A dataset is sent one only when it lists the new query feature `'shapelessDelete'` in `supports` (`SparqlDataset` does). `LinkedStorage` never fans one out: without a target it goes to the one dataset LinkedStorage knows, and is refused when it knows several. It reaches every data graph, so a receiver that runs it for a client decides who may send it. `DeleteQuery.shape` (and `DeleteBuilder.shape`) is now `NodeShapeData | undefined`; `DeleteBuilder.isShapeless` and `requiredFeatures()` are new.
