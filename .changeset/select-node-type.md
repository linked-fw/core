`$type()` in the select DSL: a node's `rdf:type` values, multi-valued IRI nodes typed `{id}`, on every shape (no property of the shape can shadow it). It works as a field (`Thing.select((t) => [t.name, t.$type()])`), as a group key (`.select((t) => ({kind: t.$type(), n: Expr.count()})).groupBy('kind')`, one group per type, so a node with two types is in two groups), in a where (`t.$type().equals({id: C})`, `.some(…)`, `.none(…)`), as a sort key and on nested paths (`p.bestFriend.$type()`). It answers what the store answers for `rdf:type`, so on an inferring store the stored and the inferred types. `$`-prefixed members are facts about the node, not shape fields; `$type` and `$graph` are reserved query names, and registering a property with either label throws. New: `equals(x)` on a multi-valued relation, which holds when some member is `x` (`p.friends.equals({id})`). DSL-JSON 1.6: the `$type` path segment, in fields, where, sortBy and group keys; `walkPropertyPath` and label selects (`select(['$type'])`) resolve it too. New exports `nodeTypePropertyShape`, `NODE_TYPE_LABEL`, `NODE_TYPE_PROPERTY_ID`.
