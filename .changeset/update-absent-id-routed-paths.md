An update of an absent id writes nothing, and routed reads follow an inverse path where it is stored.

- **Breaking: `update().for({id})` on a node that does not exist is a no-op.** Its WHERE now requires the subject's type, `FILTER(EXISTS { <id> rdf:type ?t })` (any type), in the default graph, under `WITH <g>` and inside `GRAPH ?g_w`. Before, an absent id got its properties written with no `rdf:type`, a node no shape-scoped select finds (unrouted, or a shape routed to one graph); an id with properties but no type (an untyped half-node) is not updated either. The call still resolves with the id and the fields it was given: a SPARQL update does not report what it changed. Use `upsert()` when the node may be absent; it is unchanged. A shape without a `targetClass` (which can only be updated by id) still writes whatever node it names.
- **The graph lookup of a routed change finds the subject by its type.** When a shape's read set holds several graphs, `{ SELECT DISTINCT ?g_w … GRAPH ?g_w { <s> a ?o } }` replaces `<s> ?p ?o`, so an untyped half-node in one graph no longer decides where an update, upsert or delete runs. An upsert next to such a half-node creates the node in its routed graph. (A shape without a `targetClass` is still found by any triple.)
- **Routed reads through `^<p>` read the stored triple.** Under graph routing, `?a ^<p> ?b` whose ends may live in different graphs is written `?b <p> ?a` and read in `?b`'s graphs, in selects (a traversal, or the path read as a value: `w.articles`, `w.articles.size()`), where clauses (`EXISTS` included), counts and asks: `Writer.select((w) => w.articles.title)` with `Writer.articles = ^author` finds the articles in their own graph. Before, the triple was read in the writer's graph and matched nothing.
- **Other complex paths across routed graphs are refused on reads, as on writes.** A sequence, alternative, `*`, `+` or `?` path between ends that may live in different graphs throws `GraphQueryError('unsupported-query-kind')` before anything is sent (a select wraps it as its error's `cause`). Ends that both read the same one graph compile as before. Apps without graph routes compile reads byte for byte as before.
