# 088 — Hub imports: core

## PR

### Summary

Three pieces for hosts that import packages' shapes, ontologies and components per workspace:

- **Syncs follow routing.** An app's ontology and shape graphs go into every dataset its storage
  routing needs them in, not only the default dataset; copies routing no longer needs are pruned
  in the default dataset and reported elsewhere. `graphContent()` returns the exact text and hash
  the `'package'`-mode syncs would write, so a host can be the only writer (`@_linked/server`'s
  `POST /admin/graph-content` answers it).
- **Component index vocabulary.** The terms of the `components.ttl` file `linked build` writes
  (generated by `@_linked/react`), and `ComponentsGraph`, the graph-registry record class a host
  uses to keep that file as a named graph.
- **Fixes.** `QueryBuilder.fromJSON` round-trips a null-subject query; a graph-registry record
  field given an empty list no longer produces invalid SPARQL.

The per-dataset `syncShapeGraphs(ds)` and `syncOntologies(ds)` keep their signature and meaning.

## Details

### Contract: routed sync targets (K4 in the hosting application's plan 282)

Module `@_linked/core/shapes/syncTargets` (`src/shapes/syncTargets.ts`):

- `SHAPE_SHAPE_CLASSES`, `ONTOLOGY_TERM_CLASSES`.
- `graphSyncTargets(): GraphSyncTargets` = `{shapes: Map<pkg, IDataset[]>, ontologies: Map<pkg,
  IDataset[]>, appShapes: IDataset[], datasets: IDataset[]}`; each list without duplicates, the
  default dataset first, then in pin order; `datasets` = `LinkedStorage.getDatasets()`.
- Targets are computed from routing, never configured. For each registered shape class
  (`getAllShapeClasses()`, outside any catalog), `LinkedStorage.getDatasetForShapeClass` gives its
  dataset (it falls back to the IRI, so two copies of a class resolve alike).
  - A package's **shape graph**: the datasets of its shapes ∪ the datasets of the shapes targeting
    `sh:NodeShape`/`sh:PropertyShape`.
  - A package's **ontology graph**: its shapes' datasets ∪ the datasets of any shape whose target
    class is in one of its namespaces ∪ the term shapes' datasets (inference needs the hierarchy
    where the instances are). An ontology-only package follows the shapes that target its classes.
    Core's own ontology follows core's own shapes.
  - The **single-owner (app) graph**: every dataset a shape it constrains routes to (the shapes
    declaring `contains` properties and their sub-shapes, following the prototype chain) ∪ the
    NodeShape/PropertyShape datasets; one text everywhere (`singleOwnerShapesTurtle` of all
    registered shapes).
  - With no shape targeting `sh:NodeShape`/`sh:PropertyShape` (or no term shape) registered, the
    description datasets are `{default}`. An app with no pins gets `{default}` everywhere.
- `syncShapeGraphsRouted(options)` and `syncOntologiesRouted(options)`: the per-dataset sync
  options minus `ds`, plus `prune?: boolean` (default true) and `targets?` (default
  `graphSyncTargets()`). Result `{targets: Array<{dataset: string; result: SyncShapeGraphsResult |
  SyncOntologiesResult}>, pruned: RoutedGraph[], leftovers: RoutedGraph[], failed:
  Array<{dataset: string; error: string}>}`, `RoutedGraph = {dataset, package, graph}`, `dataset`
  = `datasetLabel(ds)` (store class plus `id` or Fuseki dataset name).
  - One parse, many writes: each package's text is read and generated once, so every dataset gets
    the same bytes and hash. Shared and default modes get the dataset's package subset as members;
    the in-memory hierarchy is still set once from every package (`setHierarchyFromPackages`).
  - Prune: in every known dataset that is not a target of package P, P's package-mode graph (the
    record's `core:package` is P and the graph is P's `ShapesGraph.iriFor`/`OntologyGraph.iriFor`)
    is dropped in the default dataset and reported as a `leftover` elsewhere (one warning). Never a
    shared graph, the app graph, or another package's graph. A dataset routing no longer knows is
    not read. The registration-based orphan prune (`orphanScope: 'all'`) stays separate and
    opt-in.
  - `'default'` ontology mode on a dataset without every package: one warning per dataset and
    process naming the packages routed elsewhere.
  - A dataset that cannot be read or written fails its own target only (`failed`); the others sync.
  - A dataset class without `graphQuery` keeps the per-dataset behaviour (shapes fall back to the
    default graph; ontologies throw).
- `graphContent({packages?, turtleFor?, appShapes?})` → `{packages: [{name, shapes?, ontology?}],
  appGraph?, withoutTurtle, unreadable}`, each part a `GraphContent = {graph, mediaType:
  'text/turtle' | 'application/n-triples', text, hash, sources: string[]}`: shapes `{text, hash:
  shapeGraphHash(text), sources: ['data/shapes.ttl']}`; ontology `{text: nTriplesFromTurtle(...),
  hash: ontologyGraphHash(raw texts), sources: packageSources(pkg)}` (the hash covers the raw file
  texts, never recompute it from the text); app graph from `singleOwnerShapesTurtle`, `null` when
  there is none. A valid name the process does not know answers `{name}` with neither graph; an
  installed package without `shapes.ttl` has no `shapes` part and is listed in `withoutTurtle`.
- The per-dataset `syncShapeGraphs(ds, …)` and `syncOntologies(ds, …)` are unchanged; callers that
  pass an explicit dataset (a workspace host's own store) are never reached by routing.

`@_linked/server` consumes this: `LINKED_GRAPH_WRITER=app|host`, the routed boot sync and
`POST /admin/graph-content` (its report 025 holds that contract).

### Contract: component index vocabulary and record (K8 in plan 282)

- Terms (`https://linked.cm/ont/core/`, prefix `core:`): classes `core:Component`,
  `core:SetComponent` (`rdfs:subClassOf core:Component`), `core:ComponentsGraph`
  (`rdfs:subClassOf sd:NamedGraph`); properties `core:definesComponent` (package → component),
  `core:exportName` (`xsd:string`), `core:startShape`, `core:queryShape` (→ `sh:NodeShape`),
  `core:query` (`rdf:JSON`), `core:commit` (the commit a named graph's content was built from).
  `rdf:JSON` in core's `rdf` module.
- The file's format (enumeration, IRIs, determinism) is `@_linked/react`'s report 005.
- `ComponentsGraph` record: `ComponentsGraph.create({id, package, version?, commit?})
  .withContent(…)`, `update(iri).set({commit}).replaceContent(…)`, `delete(iri)`. The graph IRI is
  the host's choice. It never feeds the class hierarchy.
- `QueryBuilder.fromJSON` reads back `"subject":{"@ctx":"x"}`, `"subject":"<iri>"` and
  `"nullSubject":true`, with `toJSON()` equal to the input.

### Decisions that shaped it

- The routed sync is a loop over `graphSyncTargets().datasets` with each dataset's package subset;
  the per-dataset sync stays the unit.
- Prune only in the default dataset; elsewhere report (a store several apps share could hold
  another app's copy).
- A routed run where a dataset failed logs the others, then throws naming each failed dataset
  (a failed sync is never answered as a success).
- `ComponentsGraph` lives in core because the graph-record registration is private and every other
  graph kind is here.
- The empty-field fix sits in the serializer, so every record class and caller gets it.
